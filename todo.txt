# ML_ZULF Plan

## Goal

Build a staged ZULF-NMR optimizer that uses fast approximate simulation for global search and high-fidelity simulation for final refinement.

## Cleanup Decisions

- Keep `references/` as the archive of legacy code and extraction targets.
- Remove unused generic ML scaffold files from the active application.
- Keep `main.py` as the single supported launcher.
- Treat the current active app as a spectroscopy optimization tool, not a generic ML project.

## Active Problems To Solve

1. The current project still uses a single expensive optimization path for all iterations.
2. Documentation does not match the active codebase.
3. Experimental data, simulation, and scoring are too tightly coupled.
4. There is no fast backend for coarse global search.
5. There is no checkpointing or staged optimization yet.

## New Technical Plan

### Phase 1: Structural Refactor

1. [done] Introduce a backend interface for spectrum simulation.
2. [done] Keep the existing MATLAB/Spinach path as the full backend.
3. [done] Add a first minimal Python 1D fast eigen-spectrum backend.
4. [done] Route the optimizer through the backend interface instead of calling one implementation directly.
5. [done] Add CLI backend selection through `main.py --backend`.

### Phase 2: Staged Optimization

1. [done] Stage A: eigenvalue-based coarse search
   - optimize J-related parameters first
   - use peak-position dominant cost

2. [done] Stage B: Python FID refinement stage
   - use `python_fid` as the current refinement backend
   - switch backend and cost weights by stage

3. [next] Stage C: optional high-fidelity validation stage
   - keep Spinach as a validation or final ranking backend
   - decide later whether Stage C remains optional or becomes default

### Phase 3: Robustness

1. Add checkpoint save and resume.
2. Add backend agreement tests.
3. Add loader and cost edge-case tests.
4. Improve logging for optimization stage transitions and backend choice.

## Immediate Next Steps

1. Refine the fast backend weights so coarse spectra track the reference kernel more faithfully.
2. [done] Add backend agreement tests between `fast_eigen` and `python_fid` for small systems.
3. Compare both Python backends against reference outputs on the same molecules.
4. Update the UI to expose backend and staged optimization settings.
5. Add checkpointing and resume support.
